# Lead360 — Budgeting: how it works + the AI/workflow adaptation

> How Riseup Labs budgets are actually built, and how Lead360 reproduces that method with AI drafting + a workflow + full manual customization. Grounds `DATABASE_KNOWLEDGE.md` §2 (data facts) and `RAG_AI_ARCHITECTURE.md` (AI). Demonstrated in the prototype at `design/html/app/lead-detail.page.html` (Budget tab) + `client/budget-view.page.html`.

---

## 1. How Riseup's existing budgets work (verified from the real files)

Riseup budgets are **resource-based, day-rate (not hourly)**. Each line is a **role**, and its cost is:

```
Unit Cost = No. of Unit (headcount) × No. of Days × Per-Day Cost (day rate)
```

So a budget is *"how many people, of which role/seniority, for how many days, at what day-rate"* — **resource count × days × rate**, NOT hours. There is no hourly line anywhere in the corpus; everything is **man-days**.

Structure (the FIFA 9-column template, identical across all 11 real budgets):

| Sl. | Departments | Heads | Type | No. of Unit | No. of Days | Per Day Cost | Unit Cost | Total Cost |
|---|---|---|---|---|---|---|---|---|

- **One sheet per milestone** (e.g. Development, Deployment, Monthly Maintenance).
- Rows **grouped by department** — the first row of a group carries the Sl.# + department name.
- **Departments:** Managing & Planning · Art · Development · Others.
- **Type / seniority:** Senior · Mid · Junior (drives the day rate).
- **Formulas (live in the sheet):** row `Unit Cost = Unit × Days × Rate`; department **Total = SUM(group)**; sheet **Total = SUM(departments)**.
- A **timeline note** under the table ("Development Timeline = X weeks").

That's the whole method. It's deterministic arithmetic over a **rate card** — which is exactly why AI should *estimate the resource plan* but **never do the math**.

## 2. The rate card (seed — dev learns real averages per role from ingested budgets)

Day rates in USD, seniority-tiered (see the editable table in the prototype JS `RATECARD`):

| Department | Role | Senior | Mid | Junior |
|---|---|---|---|---|
| Managing & Planning | Project Manager | 120 | 95 | 70 |
| Managing & Planning | Product Designer | 90 | 75 | 55 |
| Managing & Planning | Product / Game Analyst | 100 | 80 | 60 |
| Art | UI/UX Designer | 90 | 70 | 50 |
| Art | Graphics / Motion / 2D / 3D | 80–95 | 60–72 | 45–52 |
| Development | Technical Lead | 130 | 110 | 85 |
| Development | Backend / Frontend Developer | 110 | 85 | 60 |
| Development | Unity / VR Developer | 115–120 | 90–95 | 62–65 |
| Development | DevOps | 110 | 90 | 65 |
| Development | Moodle / eLearning Expert | 100 | 80 | 60 |
| Others | QA Expert | 80 | 60 | 45 |
| Others | Trainer | 80 | 60 | 45 |
| (cross) | Solution Architect | 140 | 120 | — |

In dev these live in the `rate_card` table and are **re-learned** from every ingested/approved budget (rolling average per role+type). The card is the single source for suggested rates; a user can still override any line.

## 3. How Lead360 adapts it — AI drafts, code computes, human customizes

### 3a. Generation (the workflow)
```
Proposal scope + phases + duration
      │  (AI — one small structured call, cheap model)
      ▼
Resource plan JSON:  [{ department, role, type, unit, days }, …] per milestone
      │  (deterministic, in code — NO LLM math)
      ▼
apply rate_card → Unit Cost per line → dept subtotals → milestone subtotal
      → contingency / discount / VAT → milestone total → engagement total
      │
      ▼
Render FIFA table (web) + export .xlsx with real formulas
```
- **AI's only job** = infer the *role / seniority / count / days* mix from the scope (project type → typical crew; phase count + duration → days). Signals: game→Unity/2D-3D; VR→VR/3D; web→FE/BE/UI-UX; eLearning→Moodle/Script/Voice; gov MIS→BE/DevOps/Tech-Lead.
- **All numbers are computed in code** from the rate card — never generated by the model (guardrail: no hallucinated totals).
- **We can generate a budget for any existing DB proposal** the same way (parse its scope+duration → resource plan → compute). Where a budget already exists, we store the `scope → role-days` pair as a training example so estimates sharpen (see the learning loop in `RAG_AI_ARCHITECTURE.md`).

### 3b. Budget generation rule by template
- **Global / Local** → a **separate** Excel budget (the technical proposal references it).
- **Agency / Design Portfolio** → budget **inline** as the "Financial Proposal" section of the combined document.

## 4. Edit & customization options (what the user can change)

The budget is **AI-drafted, fully human-owned**. Everything below is editable in the prototype's Budget tab and is the spec for dev:

**Per line (role)**
- Change the **Role / Head** (dropdown from the rate-card taxonomy, or a custom name).
- Change **Type / seniority** (Senior/Mid/Junior) → **auto-fills the card day-rate**, still overridable.
- Edit **No. of Unit** (headcount), **No. of Days**, **Per-Day Rate** → Unit Cost recomputes live.
- **Remove** the line (×). **Add** a line to any department ("+ Add role").

**Per department (group)**
- **Rename** the department (inline).
- **Add** a department ("+ Add department").
- Mark a group **Optional add-ons** — hidden from the client total unless "Optional lines" is on (upsell lines).

**Per milestone (sheet)**
- **Milestone tabs** (Development, Deployment, Maintenance…); **Add milestone**; each has its own department groups.
- **Adjustments** applied to the milestone subtotal → total: **Contingency %**, **Discount %**, **VAT / Tax %** (computed and shown as line rows).

**Whole budget**
- **Currency** switch (USD base + EUR/GBP/BDT/AED/SAR) — rates are USD-base, totals convert.
- **Reset to AI estimate** (revert all manual edits to the generated draft).
- **Regenerate with AI** in plain English (delta): *"reduce DevOps to 4 days, add a senior QA lead, apply 10% contingency"* → re-drafts only what's asked, then code recomputes.
- **Export .xlsx** — mirrors the FIFA structure with **live formulas** (ExcelJS in dev), not flat values.
- **Timeline note** (weeks/months) + **engagement total** across all milestones.

**Governance**
- Rate card, department/role taxonomy, and default contingency/VAT are **admin-configurable** (Admin Settings → Rates & Currency).
- Every edit is captured: the **diff (AI draft → final)** feeds the learning loop so future drafts need fewer edits; approved budgets become gold examples and re-train the rate card.

## 5. Dev implementation notes
- Prototype demonstrates the full interaction model in vanilla JS (`RATECARD`, `MS` milestones, `renderBudget`/`recalcAll`, add/remove/reset/adjustments). In the real build:
  - Resource-plan estimate = one Haiku structured-output call; math = server/code; export = ExcelJS.
  - Persist as `generation` (versions + section JSON) + `feedback` (edit diff); rates in `rate_card`, learned samples in `role_day_sample`.
  - Keep numbers **deterministic and auditable** — the LLM proposes structure + estimates only.
