# Lead360 — Developer Handoff

Audience: a backend/DevOps engineer seeing this codebase for the first time.

## What Lead360 is

Lead360 turns a client brief into a branded proposal (PDF) and a costed budget
(Excel), grounded in Riseup Labs' own past work. An AI drafts the proposal text
using retrieval over Riseup's past proposals; pricing comes from a fixed
day-rate card and is computed in code, never generated by the AI. Sales/PM reps
create leads and admins approve them before they go to clients.

## Architecture

```
                         ┌─────────────────────┐
                         │   OpenAI Platform    │  chat + embeddings
                         │  api.openai.com/v1   │  (gpt-5.4, 768-dim embeds)
                         └──────────▲──────────┘
                                    │ HTTPS
  ┌──────────┐   HTTPS    ┌─────────┴──────────┐   TCP    ┌──────────────────┐
  │ Browser  │ ─────────► │  NestJS API        │ ───────► │ PostgreSQL 16    │
  │ (cookie) │ ◄───────── │  :3000  /api       │ ◄─────── │  + pgvector      │
  └──────────┘            │  4-layer + guards  │          │  (HNSW indexes)  │
       ▲                  └─────────┬──────────┘          └──────────────────┘
       │ static SPA                 │
  ┌────┴──────────────┐             │ writes files
  │ React Router 7    │             ▼
  │ SPA  :5173        │    ┌────────────────────┐
  │ Redux + Axios     │    │ Object storage     │  local dev → backend/uploads
  └───────────────────┘    │ local | r2 | s3    │  prod → R2 / S3
                           └────────────────────┘
                    (FX rates: outbound HTTPS to FX_API_URL on admin "Sync")
```

The browser loads the React SPA from `:5173`; the SPA calls the NestJS API at
`:3000` under the `/api` prefix. Auth is a JWT in an httpOnly, SameSite=strict
cookie — never localStorage. Every route is protected by a global
`JwtAuthGuard` + `RolesGuard` unless explicitly marked `@Public()`.

## Stack

- Backend: NestJS 10, TypeORM 0.3.20, `pg` 8, PostgreSQL 16 + pgvector, ExcelJS
  4.4 (budget .xlsx), Puppeteer 23 (proposal PDF), OpenAI SDK 6, bcrypt.
- Frontend: React 18, React Router 7 (framework mode), Redux Toolkit 2, Axios
  1.7, Tailwind CSS v4.
- Node: developed on v24; no `engines` field is declared. Use **Node 20 LTS or
  newer**.

## Local setup

Prerequisites: Node 20+, Docker (for Postgres), and an OpenAI API key.

Run in order. Working directory is stated for each block.

**1. Start the database** (in `d:\lead360`, the repo root):

```bash
cp .env.example .env
# edit .env: set POSTGRES_PASSWORD to any local dev value
docker compose up -d
```

The root `.env` configures only the Postgres container. Its `POSTGRES_*` values
must match the `DATABASE_*` values you set in `backend/.env` next.

**2. Configure the backend** (in `d:\lead360\backend`):

```bash
cp .env.example .env
```

Fill in these `backend/.env` values:

- `DATABASE_PASSWORD` — same value you put in the root `.env`.
- `AI_API_KEY` — your OpenAI key (`sk-proj-...`).
- `JWT_SECRET` and `JWT_REFRESH_SECRET` — two **different** random strings.
  Generate each with:

  ```bash
  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ```

The app throws `JWT_SECRET is required` at boot if that value is missing — there
is no fallback.

**3. Install, seed, ingest, run** (in `d:\lead360\backend`):

```bash
npm install
npm run seed            # creates users + base data from _fixtures.yaml
npm run ingest:head-cost   # loads the day-rate card (52 roles, 8 departments)
npm run ingest:riseup      # chunks + embeds past proposals into pgvector
npm run start:dev
```

`npm run ingest:riseup` calls the OpenAI embeddings API — it **costs money and
takes time** (it embeds the whole `backend/data/kb-seed/` corpus). Run it once
on a fresh database; you do not need to rerun it unless the corpus or the
embedding model changes.

`npm run ingest:head-cost` is the authoritative rate loader. There is an older
`npm run ingest:rates` that derived medians from past budgets — it is superseded;
use `ingest:head-cost`.

**4. Run the frontend** (in `d:\lead360\frontend`):

```bash
cp .env.example .env
npm install
npm run dev
```

**5. Log in** at http://localhost:5173 with the admin credentials below.

## Production checklist

- `DATABASE_SYNCHRONIZE=false` — and run `npm run migration:run` to apply
  schema. Never leave synchronize on in staging/production (see gotcha below).

  Verified on 2026-07-10: running the five migrations against an **empty**
  database produces a schema identical to the running development database —
  24 tables, 247 columns, 12 enums, and both pgvector columns with their HNSW
  indexes. You do not need to bootstrap with `synchronize` first.

  Two of those migrations are recent and worth knowing about.
  `SyncEntitiesToSchema` backfills four tables (`invitations`, `org_settings`,
  `lead_comments`, `portfolio_projects`) that had until then only ever been
  created by `synchronize`. `AddPortfolioEmbedding` adds
  `portfolio_projects.embedding` — TypeORM cannot manage the `vector` type, so
  `migration:generate` silently omits such columns. If you ever add another
  vector column, write that migration by hand; the generator will not.
- `COOKIE_SECURE=true` (you are on HTTPS).
- `STORAGE_PROVIDER=r2` or `s3` with real bucket credentials. `local` is not
  durable and is not shared across pods.
- Distinct, strong `JWT_SECRET` and `JWT_REFRESH_SECRET` (not the dev values).
- `CORS_ORIGIN` = the real frontend origin, exactly. A mismatch drops the auth
  cookie and every request looks unauthenticated.
- `APP_URL` = the real frontend origin (used to build invitation links).
- Allow outbound HTTPS to `api.openai.com` and to `FX_API_URL`
  (`open.er-api.com` by default).
- **Rotate the OpenAI API key** before production — the current key was shared
  in plain text previously and must be considered compromised.
- Puppeteer needs a Chromium sandbox for PDF generation. In Docker either
  install the Chromium system dependencies in the image, or launch with
  `--no-sandbox`. `--no-sandbox` is simpler but removes a process-isolation
  boundary; only do it if the container itself is the trust boundary. Document
  whichever you choose.

## Gotchas (symptom first)

- **Symptom: on every boot the log prints errors about dropping an index, then
  recreates it.** `DATABASE_SYNCHRONIZE=true` makes TypeORM drop columns and
  indexes it does not model — including the pgvector HNSW indexes, which it
  tries to drop each boot. Harmless in local dev; must be `false` in
  staging/production, with `npm run migration:run` instead.
- **Symptom: RAG search returns nothing or throws a dimension mismatch after a
  model change.** Embeddings are pinned to **768 dimensions** to match the
  pgvector columns. Changing `AI_EMBED_MODEL` requires re-embedding everything:
  `npm run ingest:riseup` then `POST /api/portfolio/embed`. See
  `AI_MODEL_GUIDE.md`.
- **Symptom: login succeeds but the next request is unauthenticated / cookie
  missing.** Either `CORS_ORIGIN` does not exactly match the frontend origin, or
  `COOKIE_SECURE=true` is set while serving over plain HTTP. Fix the mismatch.
- **Symptom: prices look off by 100x.** Money is stored as integer **cents** in
  `bigint` columns and serialised as strings. Divide by 100 for display; do not
  treat the string as a float.
- **Symptom: a role you expected is missing from the budget.** A role that is
  not on the head-cost rate card is **skipped, never invented**. The AI does not
  price anything. Add the role to the rate card and re-run `ingest:head-cost`.
- **Symptom: no email is sent when inviting a user.** Email is disabled by
  design (`EMAIL_ENABLED=false`). The invite endpoint returns a copyable link
  the admin sends manually. Do not enable email without a product decision.
